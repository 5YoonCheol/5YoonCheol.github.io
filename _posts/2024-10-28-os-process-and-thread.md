OS 공부하면 제일 먼저 나오는 게 프로세스와 스레드다. 면접에서도 단골 질문이라 한 번 제대로 정리해두려고 한다.

### 1. 프로세스 (Process)

프로세스는 실행 중인 프로그램이다. 프로그램을 실행하면 운영체제가 메모리 공간과 시스템 자원을 내어 주고, 그렇게 만들어진 독립적인 작업 단위가 프로세스다.

#### 특징

- 메모리를 따로 쓴다: 실행에 필요한 메모리(코드, 데이터, 힙, 스택)를 각자 갖고 있고, 다른 프로세스와 공유하지 않는다.
- 운영체제가 관리한다: 프로세스 상태, CPU 할당, 메모리를 OS가 관리하고 프로세스끼리 자원 접근도 조율한다.
- 만드는 비용이 크다: 메모리 공간을 통째로 새로 잡아야 해서 새 프로세스를 만들 때 자원이 많이 든다.
- 서로 영향을 주지 않는다: 여러 프로세스를 동시에 돌리는 멀티 프로세싱이 가능하고, 각자 독립적으로 돌아간다.

#### 메모리 구성

- 코드 영역 (Code Segment): 실행할 프로그램 코드
- 데이터 영역 (Data Segment): 전역 변수, 정적 변수
- 힙 영역 (Heap Segment): 동적으로 할당하는 메모리
- 스택 영역 (Stack Segment): 함수 호출 시 지역 변수, 매개변수

#### 상태

- 생성 (New): 막 만들어진 상태
- 준비 (Ready): 실행할 준비가 된 상태
- 실행 (Running): CPU를 잡고 실제로 돌고 있는 상태
- 대기 (Waiting): 자원이나 I/O를 기다리느라 잠깐 멈춘 상태
- 종료 (Terminated): 실행이 끝났거나 중단된 상태

### 2. 스레드 (Thread)

스레드는 프로세스 안에서 실제로 일을 하는 실행 단위다. 프로세스 하나에 스레드가 하나 이상 있을 수 있고, 스레드들은 프로세스의 자원을 같이 쓰면서 동시에 작업한다.

#### 특징

- 프로세스의 일부다: 같은 프로세스의 자원을 공유하고, 한 프로세스 안에서 여러 스레드가 동시에 돈다.
- 가볍다: 메모리 공간을 따로 잡지 않으니 프로세스보다 만들기 빠르고 자원도 덜 든다.
- 멀티스레딩: 스레드를 여러 개 띄워서 병렬로 일하면 성능을 올릴 수 있다. 웹 서버가 요청마다 스레드를 할당해서 여러 요청을 동시에 처리하는 게 그 예다.

#### 스레드가 따로 갖는 것

- 스택: 함수 호출과 지역 변수는 스레드마다 따로 쌓인다.
- 레지스터: CPU가 작업할 때 쓰는 레지스터 상태도 스레드마다 따로 관리된다.
- 프로그램 카운터: 각 스레드가 어디까지 실행했는지 추적한다.

#### 장단점

자원을 공유하니 프로세스보다 메모리와 CPU를 덜 쓰고, 스레드끼리 데이터를 주고받기도 빠르다.

대신 공유하는 만큼 동기화 문제가 생길 수 있고, 스레드 하나가 오류를 내면 프로세스 전체가 영향을 받을 수 있다.

---

### 3. 프로세스와 스레드 비교

| 구분 | 프로세스 | 스레드 |
| --- | --- | --- |
| 메모리 | 독립된 메모리 영역 | 같은 프로세스 안에서 공유 |
| 자원 소모 | 많음 | 비교적 적음 |
| 독립성 | 다른 프로세스와 독립적 | 같은 프로세스의 다른 스레드에 영향을 줄 수 있음 |
| 오류 영향 | 다른 프로세스에는 영향 없음 | 프로세스 전체에 영향을 줄 수 있음 |
| 생성 속도 | 상대적으로 느림 | 상대적으로 빠름 |

### 4. 예시로 보면

- 프로세스: 웹 브라우저와 워드 프로세서를 같이 켜면 둘은 서로 다른 프로세스로 돌아간다.
- 스레드: 한 애플리케이션 안에서 여러 일을 동시에 할 때 쓴다. 예를 들어 브라우저에서 여러 탭이 동시에 페이지를 불러오는 식이다.
