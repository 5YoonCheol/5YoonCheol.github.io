오늘은 자주 쓰는 반복문 얘기를 해보려 한다.

Java의 기본 for문과 향상된 for문을 간단히 살펴보고, 둘의 장단점과 차이를 비교해보자.

---

### 기본 for문과 향상된 for문

### 1. 기본 for문

반복 횟수를 정해두거나, 인덱스로 배열이나 리스트의 요소를 하나씩 볼 때 주로 쓴다.

```java
for (초기화; 조건; 증감) {
    // 실행할 코드
}
```

초기화 부분에서 반복에 쓸 변수를 선언하고, 조건 부분에 반복을 계속할 조건을 적고, 증감 부분에서 매번 변수 값을 바꾼다.

예시:

```java
for (int i = 0; i < 5; i++) {
    System.out.println("i의 값: " + i);
}
```

i가 0부터 4까지 출력된다. 처음에 i는 0이고 한 번 돌 때마다 1씩 늘어난다. 조건이 `i < 5`라서 i가 5가 되는 순간 반복이 끝난다.

### 2. 향상된 for문

배열이나 컬렉션의 요소를 처음부터 끝까지 훑을 때 쓴다. 기본 for문보다 짧고 읽기 편하다.

```java
for (타입 변수 : 배열 또는 컬렉션) {
    // 실행할 코드
}
```

배열이나 컬렉션의 요소를 앞에서부터 하나씩 꺼내 변수에 담고, 그 변수로 코드를 실행한다.

예시:

```java
int[] numbers = {1, 2, 3, 4, 5};
for (int number : numbers) {
    System.out.println("number의 값: " + number);
}
```

numbers 배열의 요소를 하나씩 number에 담아서 출력한다.

---

### 장단점과 차이

### 1. 기본 for문

좋은 점은 인덱스를 직접 다룰 수 있다는 거다. 특정 인덱스를 건너뛰거나 값을 조정할 수 있고, 시작점, 종료 조건, 증가폭도 마음대로 정할 수 있다. 짝수 인덱스만 처리하거나 거꾸로 도는 것도 된다. 다중 루프나 조건에 따라 달라지는 반복처럼 복잡한 경우에도 맞다.

대신 단순히 배열을 한 바퀴 도는 경우에도 초기화, 조건, 증감을 다 적어야 해서 코드가 길어진다. 조건이나 증감을 잘못 쓰면 무한 루프에 빠지거나 엉뚱하게 동작할 수도 있다.

### 2. 향상된 for문 (Enhanced for Loop)

전체 요소를 순회할 때 코드가 짧고 바로 읽힌다. 인덱스를 직접 만지지 않으니 배열 범위를 넘거나 무한 루프에 빠지는 실수도 줄어든다.

아쉬운 점도 있다.

- 요소에 순서대로 접근만 할 뿐 지금 몇 번째인지 알 수 없다. 특정 인덱스만 건너뛰는 것도 안 된다.
- 순회 도중에 요소를 바꾸거나 컬렉션에 추가/삭제를 하면 문제가 생길 수 있다.
- 조건에 따라 반복 흐름을 조정하는 복잡한 루프는 만들기 어렵다.

### 3. 한눈에 비교

| 항목 | 기본 for문 | 향상된 for문 |
| --- | --- | --- |
| 인덱스 접근 | 가능 | 불가능 |
| 코드 간결성 | 상대적으로 복잡 | 매우 간결 |
| 조건 및 증감 설정 | 자유로움 | 제한적(불가) |
| 복잡한 반복문 | 적합 | 부적합 |
| 안전성 | 오류 발생 가능성 있음 | 상대적으로 안전 |

### 정리

반복 횟수나 인덱스를 직접 다뤄야 하면 기본 for문, 그냥 처음부터 끝까지 도는 거면 향상된 for문을 쓰면 된다.
