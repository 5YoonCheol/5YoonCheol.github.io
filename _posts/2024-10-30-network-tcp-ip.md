TCP/IP는 **인터넷 프로토콜 스위트**라고도 불리며, 인터넷과 네트워크 통신을 가능하게 하는 **표준 통신 프로토콜 모음**이다. TCP/IP는 여러 계층으로 구성되어 있으며, 각 계층에서 데이터의 전달, 패킷 분할, 전송 경로 설정, 오류 검출 등의 역할을 수행한다.

### TCP/IP의 계층 구조

TCP/IP는 총 4계층으로 구성되어 있으며, 각각의 계층은 특정한 역할을 담당한다.

1. **응용 계층 (Application Layer)**: 사용자와 가장 가까운 계층으로, 다양한 네트워크 서비스를 제공한다. HTTP, FTP, SMTP 등이 여기에 속한다.
2. **전송 계층 (Transport Layer)**: 통신 세션을 관리하고 데이터의 정확한 전달을 보장하는 역할을 한다. 대표적인 프로토콜로 TCP와 UDP가 있다.
3. **인터넷 계층 (Internet Layer)**: 데이터 패킷의 경로를 결정하고 네트워크 간 전송을 관리한다. 주요 프로토콜로는 IP, ICMP, ARP 등이 있다.
4. **네트워크 인터페이스 계층 (Network Interface Layer)**: 물리적 데이터 전송을 담당하며, 실제 네트워크 장치(이더넷, 와이파이 등)와 데이터를 주고받는다.

### TCP/IP 계층별 역할과 프로토콜

#### 1. 응용 계층

응용 계층은 사용자가 직접 접근할 수 있는 계층으로, 네트워크를 통한 응용 서비스들이 포함되어 있다. 응용 계층 프로토콜은 다양한 네트워크 응용 프로그램이 상호 작용할 수 있도록 도와준다.

- **HTTP/HTTPS**: 웹 페이지를 전송하는 프로토콜이다. HTTPS는 HTTP에 SSL/TLS 암호화를 더해 보안을 강화한 버전이다.
- **FTP**: 파일 전송 프로토콜로, 네트워크를 통해 파일을 전송할 수 있도록 해준다.
- **SMTP**: 이메일 전송을 위한 프로토콜이다.
- **DNS**: 도메인 이름을 IP 주소로 변환하는 서비스이다.

#### 2. 전송 계층

전송 계층은 호스트 간의 데이터 전달을 관리하고, 데이터의 신뢰성과 정확성을 보장하는 역할을 한다.

- **TCP (Transmission Control Protocol)**: 신뢰성 있는 데이터 전송을 보장하는 연결형 프로토콜로, 데이터의 손실, 순서 변경 등을 방지하기 위해 오류 검출과 재전송 기능을 갖추고 있다. TCP는 연결을 설정한 후에 데이터 전송이 시작되며, 전송이 끝나면 연결을 해제한다. 이를 **3-way Handshake**와 **4-way Handshake**라고 한다.
- **UDP (User Datagram Protocol)**: 신뢰성보다 속도를 우선시하는 비연결형 프로토콜로, 데이터 검증이나 순서 보장이 필요 없는 애플리케이션에서 주로 사용된다. 예를 들어, 실시간 동영상 스트리밍과 같은 상황에서는 UDP가 TCP보다 효율적이다.

#### 3. 인터넷 계층

인터넷 계층은 **네트워크 간의 라우팅과 패킷 전달**을 담당한다. 데이터를 여러 네트워크를 통해 전달하기 위해 네트워크 주소(IP 주소)를 이용하며, 경로 설정을 포함하여 패킷을 목적지까지 전달한다.

- **IP (Internet Protocol)**: 각 패킷에 송신자와 수신자의 IP 주소를 부여하고, 패킷이 정확한 경로로 전달될 수 있도록 라우팅 기능을 제공한다. 현재 IPv4와 IPv6가 사용되고 있다.
- **ICMP (Internet Control Message Protocol)**: 오류 메시지와 진단 메시지를 전달하기 위해 사용된다. ping 명령어에서 사용되며, 네트워크 연결 상태를 확인하는 데 도움이 된다.
- **ARP (Address Resolution Protocol)**: IP 주소를 MAC 주소로 변환하기 위해 사용된다. 네트워크 상의 각 장치가 서로 통신하기 위해 필요한 정보를 제공한다.

#### 4. 네트워크 인터페이스 계층

네트워크 인터페이스 계층은 **데이터가 실제 네트워크 매체(케이블, 무선 등)를 통해 전달되는 과정을 관리**한다. 이 계층은 하드웨어와 관련된 물리적 전송을 담당하며, 데이터 링크 계층과 물리 계층을 합친 역할을 수행한다.

- **Ethernet**: LAN(근거리 통신망)에서 데이터를 전송하는 프로토콜.
- **Wi-Fi**: 무선 네트워크 프로토콜로, 무선 LAN에서 데이터를 전송하는 역할.

### TCP/IP의 작동 방식

TCP/IP 통신 과정은 각 계층이 데이터를 상호 교환하며 목적지에 전달하는 형태로 작동한다. 데이터를 전송할 때 각 계층은 데이터를 자신의 프로토콜에 맞게 캡슐화하며, 반대편에서 데이터가 도착하면 캡슐화를 해제하여 응용 계층까지 전달한다.

#### 예시: 웹 페이지 요청

1. **응용 계층**: 웹 브라우저가 HTTP 요청을 생성한다.
2. **전송 계층**: HTTP 요청을 TCP 세그먼트로 캡슐화하고, 송신자와 수신자의 포트 번호를 지정하여 데이터를 전송한다.
3. **인터넷 계층**: TCP 세그먼트를 IP 패킷으로 캡슐화하고, 송신자와 수신자의 IP 주소를 부여한다. 이후 패킷은 최적 경로로 라우팅된다.
4. **네트워크 인터페이스 계층**: 패킷을 프레임 형태로 변환하여 물리적 네트워크로 전송한다. 프레임은 네트워크 장치(라우터, 스위치)를 거쳐 최종 목적지로 전달된다.

수신 측에서는 반대로 데이터를 수신하여 계층을 거치며 캡슐화를 해제하고, 최종적으로 웹 브라우저가 요청한 웹 페이지를 보여준다.

### TCP와 UDP의 차이점

| **구분** | **TCP** | **UDP** |
| --- | --- | --- |
| **연결 방식** | 연결형 (3-way handshake) | 비연결형 |
| **신뢰성** | 높은 신뢰성 보장 (재전송, 순서 보장) | 신뢰성 보장 없음 |
| **속도** | 상대적으로 느림 | TCP보다 빠름 |
| **주요 사용 예** | HTTP, FTP, 이메일 | 실시간 스트리밍, 온라인 게임 |
| **오류 검출** | 있음 | 없음 (단, 최소한의 오류 검출 기능만 있음) |

### TCP/IP의 장점과 단점

#### 장점

- **표준화된 프로토콜**: 모든 네트워크 장치가 통신할 수 있는 표준이 되어 다양한 네트워크에서 호환된다.
- **확장성**: IPv6를 통해 더 많은 주소 공간이 제공되며, 인터넷 확장에 유리하다.
- **안정성**: 다중 경로와 오류 검출, 재전송 등을 통해 높은 안정성을 보장한다.

#### 단점

- **복잡성**: 네트워크 장비와 운영체제에 높은 복잡성을 요구한다.
- **오버헤드**: TCP의 신뢰성 보장을 위한 추가 데이터 전송으로 인해 오버헤드가 발생한다.
- **보안 문제**: 기본적으로 암호화되지 않아 별도의 보안 프로토콜이 필요하다(예: HTTPS, IPsec).
