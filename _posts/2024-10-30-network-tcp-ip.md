TCP/IP는 인터넷에서 컴퓨터끼리 통신할 때 쓰는 표준 프로토콜 묶음이다. 인터넷 프로토콜 스위트라고도 부른다. 여러 계층으로 나뉘어 있고, 계층마다 데이터 전달, 패킷 분할, 경로 설정, 오류 검출 같은 일을 나눠 맡는다.

### 4개의 계층

TCP/IP는 4계층으로 되어 있다. 위에서부터 보면 이렇다.

1. 응용 계층 (Application Layer): 사용자와 제일 가까운 계층. HTTP, FTP, SMTP 등이 여기 속한다.
2. 전송 계층 (Transport Layer): 통신 세션을 관리하고 데이터가 제대로 전달되게 한다. TCP와 UDP가 대표적이다.
3. 인터넷 계층 (Internet Layer): 패킷이 어떤 경로로 갈지 정하고 네트워크 사이 전송을 관리한다. IP, ICMP, ARP 등이 있다.
4. 네트워크 인터페이스 계층 (Network Interface Layer): 이더넷, 와이파이 같은 실제 장치를 통해 데이터를 물리적으로 보낸다.

### 계층별로 하는 일

#### 1. 응용 계층

사용자가 직접 쓰는 네트워크 서비스들이 있는 계층이다. 응용 프로그램끼리 네트워크로 대화할 수 있게 해준다.

- HTTP/HTTPS: 웹 페이지를 주고받는 프로토콜. HTTPS는 HTTP에 SSL/TLS 암호화를 더한 것
- FTP: 파일 전송
- SMTP: 이메일 전송
- DNS: 도메인 이름을 IP 주소로 바꿔준다

#### 2. 전송 계층

호스트 사이에서 데이터가 정확하게 전달되도록 관리한다.

**TCP (Transmission Control Protocol)** 는 연결을 맺고 통신하는 프로토콜이다. 데이터가 빠지거나 순서가 뒤바뀌지 않게 오류 검출과 재전송을 해준다. 연결을 먼저 설정하고 데이터를 보낸 뒤 연결을 끊는데, 이 과정을 각각 3-way Handshake, 4-way Handshake라고 한다.

**UDP (User Datagram Protocol)** 는 연결 없이 보내는 프로토콜이다. 신뢰성보다 속도가 우선이라 검증이나 순서 보장이 필요 없는 곳에서 쓴다. 실시간 동영상 스트리밍 같은 경우엔 TCP보다 UDP가 낫다.

#### 3. 인터넷 계층

네트워크와 네트워크 사이에서 패킷을 어디로 보낼지(라우팅) 정하고 전달하는 계층이다. IP 주소를 보고 경로를 잡아서 목적지까지 보낸다.

- IP (Internet Protocol): 패킷마다 보내는 쪽과 받는 쪽 IP 주소를 붙이고, 올바른 경로로 가도록 라우팅한다. 지금은 IPv4와 IPv6를 같이 쓴다.
- ICMP (Internet Control Message Protocol): 오류나 진단 메시지를 전달한다. `ping` 명령이 이걸 쓴다.
- ARP (Address Resolution Protocol): IP 주소를 MAC 주소로 바꿔준다. 같은 네트워크 안의 장치끼리 통신하려면 이게 필요하다.

#### 4. 네트워크 인터페이스 계층

데이터가 케이블이나 무선 같은 실제 매체를 타고 넘어가는 부분을 관리한다. OSI 7계층으로 치면 데이터 링크 계층과 물리 계층을 합친 역할이다.

- Ethernet: LAN(근거리 통신망)에서 데이터를 보내는 프로토콜
- Wi-Fi: 무선 LAN에서 데이터를 보내는 프로토콜

### 실제로는 어떻게 동작하나

데이터를 보낼 때는 위 계층에서 아래 계층으로 내려가면서 각 계층이 자기 프로토콜에 맞게 데이터를 한 겹씩 감싼다(캡슐화). 받는 쪽에서는 반대로 아래에서 위로 올라가면서 한 겹씩 벗겨서 응용 계층까지 올려준다.

웹 페이지 하나를 요청하는 과정으로 보면 이렇다.

1. 응용 계층: 브라우저가 HTTP 요청을 만든다.
2. 전송 계층: HTTP 요청을 TCP 세그먼트로 감싸고, 보내는 쪽과 받는 쪽 포트 번호를 붙인다.
3. 인터넷 계층: TCP 세그먼트를 IP 패킷으로 감싸고 IP 주소를 붙인다. 그다음 최적 경로로 라우팅된다.
4. 네트워크 인터페이스 계층: 패킷을 프레임으로 바꿔서 물리 네트워크로 내보낸다. 프레임은 라우터, 스위치를 거쳐 목적지에 도착한다.

받는 쪽은 이걸 거꾸로 풀어서, 결국 브라우저가 요청한 웹 페이지를 보여주게 된다.

### TCP와 UDP 비교

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 방식 | 연결형 (3-way handshake) | 비연결형 |
| 신뢰성 | 높음 (재전송, 순서 보장) | 보장 없음 |
| 속도 | 상대적으로 느림 | TCP보다 빠름 |
| 주요 사용 예 | HTTP, FTP, 이메일 | 실시간 스트리밍, 온라인 게임 |
| 오류 검출 | 있음 | 최소한의 검출만 있음 |

### 장점과 단점

TCP/IP는 사실상 모든 네트워크 장치가 따르는 표준이라 어디서든 호환된다. IPv6로 주소 공간도 크게 늘어나서 확장에도 유리하고, 여러 경로와 오류 검출, 재전송 덕분에 안정적이다.

반대로 아쉬운 점도 있다.

- 네트워크 장비와 운영체제 입장에서는 구현이 꽤 복잡하다.
- TCP가 신뢰성을 위해 주고받는 추가 데이터 때문에 오버헤드가 생긴다.
- 기본적으로 암호화가 안 되기 때문에 HTTPS, IPsec 같은 보안 프로토콜을 따로 써야 한다.
