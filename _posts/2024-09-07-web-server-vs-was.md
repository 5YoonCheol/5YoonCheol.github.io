WS(Web Server)와  WAS(Web Application Server)는 웹 애플리케이션을 제공하는 데 사용되는 서버 소프트웨어를 의미하며, 둘 다 웹 기술의 중요한 부분이다. 그러나 그 역할과 기능에는 차이가 있다.

오늘 포스팅에서는 WS와 WAS의 차이점에 대해 알아보자.

---

### 1. **Web Server (WS)**

- **기본 역할**: Web Server는 클라이언트(주로 웹 브라우저)로부터 HTTP 요청을 받아 정적 콘텐츠(HTML, CSS, 이미지 파일 등)를 제공하는 역할을 한다. 이 서버는 주로 정적 파일을 제공하고, 요청된 리소스를 반환하는 데 중점을 둔다.
- **주요 기능**:
  - **정적 콘텐츠 제공**: HTML, CSS, JavaScript 파일, 이미지, 비디오와 같은 정적 리소스를 클라이언트에게 전달한다.
  - **HTTP 요청 처리**: 클라이언트가 보낸 HTTP 요청을 받고, 해당 요청에 대한 응답(주로 정적 파일)을 반환한다.
  - **리버스 프록시**: 때로는 Web Server가 리버스 프록시로 동작하여, 요청을 WAS나 다른 서버로 전달할 수도 있다.
- **예시**: Apache HTTP Server, Nginx, Microsoft IIS
- **사용 예**: 간단한 웹 사이트(블로그, 포트폴리오 사이트 등)나 WAS의 앞단에 위치하여 정적 리소스를 처리하고, 동적 요청을 WAS에 전달하는 데 사용된다.

---

### 2. **Web Application Server (WAS)**

- **기본 역할**: Web Application Server는 동적 콘텐츠를 생성하고 제공하는 역할을 담당한다. 이 서버는 웹 애플리케이션 로직을 처리하고, 데이터베이스와의 상호작용을 통해 클라이언트 요청에 대한 동적 응답을 생성한다.
- **주요 기능**:
  - **동적 콘텐츠 생성**: 사용자 요청에 따라 동적으로 생성된 HTML, JSON, XML 등의 콘텐츠를 제공한다. 이 과정에서 데이터베이스와의 상호작용이 포함될 수 있다.
  - **비즈니스 로직 처리**: 애플리케이션의 핵심 비즈니스 로직을 실행하여 요청을 처리한다. 예를 들어, 사용자의 입력을 처리하거나 데이터베이스에서 데이터를 가져오는 작업 등이 포함된다.
  - **세션 관리**: 클라이언트의 세션을 관리하여 로그인 상태 유지, 사용자별 데이터 처리 등을 수행한다.
  - **트랜잭션 관리**: 데이터베이스 트랜잭션을 관리하여 데이터 일관성을 보장한다.
- **예시**: Apache Tomcat, IBM WebSphere, Oracle WebLogic, JBoss
- **사용 예**: 복잡한 비즈니스 로직을 처리해야 하는 대규모 웹 애플리케이션, e커머스 플랫폼, 포털 사이트 등에서 사용된다.

---

### 3. **비교 정리**

| **특성** | **Web Server (WS)** | **Web Application Server (WAS)** |
| --- | --- | --- |
| **기능** | 정적 콘텐츠(HTML, CSS, 이미지 등) 제공 | 동적 콘텐츠 생성 및 비즈니스 로직 처리 |
| **주요 역할** | HTTP 요청을 받아 정적 파일 반환 | 웹 애플리케이션의 동적 처리 및 데이터베이스 연동 |
| **예시** | Apache HTTP Server, Nginx | Apache Tomcat, WebSphere, WebLogic |
| **사용 예** | 간단한 웹 사이트, WAS의 프록시 서버 | 대규모 웹 애플리케이션, e커머스 사이트 등 |
| **복잡** | 상대적으로 단순 | 상대적으로 복잡, 다양한 기능 포함 |

---

### 4. **동작 원리**

- **WS**: 클라이언트가 웹 페이지를 요청하면 Web Server는 요청된 정적 리소스를 찾아 그대로 반환한다. Web Server는 클라이언트의 요청에 대한 기본적인 응답을 빠르게 처리하도록 설계되었다.
- **WAS**: 클라이언트가 웹 애플리케이션을 통해 데이터나 동적 페이지를 요청하면, WAS는 해당 요청을 처리하기 위해 비즈니스 로직을 실행하고, 필요한 데이터를 데이터베이스에서 가져와 동적으로 콘텐츠를 생성한 후 응답한다.

---

### **결론**

Web Server와 Web Application Server는 서로 다른 목적과 역할을 가진 서버 소프트웨어이다.

Web Server는 주로 정적 콘텐츠를 제공하는 데 중점을 두며, WAS는 동적 콘텐츠를 생성하고 비즈니스 로직을 처리하는 데 중점을 둔다.

대부분의 웹 애플리케이션은 이 두 서버를 함께 사용하여, 정적 콘텐츠는 Web Server가 처리하고, 동적 콘텐츠는 WAS가 처리하도록 구성한다.
