개발하다 보면 별의별 오류를 다 만나게 된다.

오늘은 웹 서버와 클라이언트가 통신하다가 마주치는 HTTP 오류에 대해 알아보자.

---

### HTTP 오류란?

웹 서버와 클라이언트(주로 웹 브라우저)가 통신하는 중에 생긴 문제를 상태 코드로 알려주는 거다. 상태 코드는 첫 자리 숫자에 따라 5가지로 나뉜다.

---

### 상태 코드 종류

### 1. 1xx (정보 응답)

요청을 받아서 처리 중이라는 정보성 응답이다. 오류라기보다는 상태를 알려주는 용도다.

### 2. 2xx (성공 응답)

요청이 잘 처리됐다는 뜻이다. 오류가 아니라 정상 응답이다.

- 예: 200 OK (정상적으로 요청이 처리됨)

### 3. 3xx (리다이렉션 응답)

요청한 리소스가 다른 곳으로 옮겨졌으니 클라이언트가 새 위치로 다시 요청해야 한다는 뜻이다.

- 예: 301 Moved Permanently (영구적으로 이동됨), 302 Found (임시 이동됨)

### 4. 4xx (클라이언트 오류)

클라이언트 쪽에서 요청을 잘못 보냈을 때 난다.

- 400 Bad Request: 서버가 요청을 이해하지 못하거나 형식이 잘못된 요청을 받았을 때.
- 401 Unauthorized: 인증이 필요한 리소스에 인증 없이 접근했을 때.
- 403 Forbidden: 요청은 이해했지만 접근 권한이 없을 때.
- 404 Not Found: 요청한 리소스를 찾을 수 없을 때. 제일 자주 보는 오류다.
- 405 Method Not Allowed: 요청한 메서드를 지원하지 않을 때.

### 5. 5xx (서버 오류)

서버 쪽 문제로 요청을 처리하지 못했을 때 난다.

- 500 Internal Server Error: 서버가 예상 못 한 상황을 만나 요청을 처리할 수 없을 때.
- 502 Bad Gateway: 게이트웨이나 프록시 서버가 잘못된 응답을 받았을 때.
- 503 Service Unavailable: 서버가 일시적으로 과부하 상태거나 점검 중일 때.
- 504 Gateway Timeout: 게이트웨이나 프록시 서버가 다른 서버로부터 제때 응답을 못 받았을 때.
