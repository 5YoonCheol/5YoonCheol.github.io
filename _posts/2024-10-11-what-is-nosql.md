NoSQL은 전통적인 관계형 데이터베이스(RDBMS)와는 다른 방식으로 데이터를 저장하고 관리하는 데이터베이스를 통틀어 부르는 말이다.

이번엔 NoSQL의 개념과 특징, 종류, 장단점을 정리해보자.

---

### 1. NoSQL이란

RDBMS는 정해진 구조의 데이터를 테이블에 저장하고, 정규화로 중복을 최소화한다. 반면 NoSQL은 스키마를 유연하게 가져가고 문서, 그래프, 키-값 같은 여러 형태로 데이터를 저장할 수 있다.

수평 확장, 고가용성, 빅데이터 처리에 강해서 웹 서비스, 모바일 앱, IoT 쪽에서 많이 쓴다.

---

### 2. 특징

- 스키마가 유연하다: 스키마를 미리 정해둘 필요가 없어서, 데이터 형태가 자주 바뀌는 환경에서도 대응하기 쉽다.
- 수평 확장이 된다: 데이터가 늘면 서버(노드)를 추가해서 성능을 늘린다. 데이터가 많을수록 유리하다.
- 분산 구조와 고가용성: 데이터를 여러 노드에 복제하고 나눠서 처리하기 때문에, 장애가 나도 데이터에 접근할 수 있다.
- ACID 대신 BASE: RDBMS는 트랜잭션 일관성을 위해 ACID를 지키지만, NoSQL은 가용성을 우선해서 BASE(Basically Available, Soft state, Eventual consistency)를 따른다.

---

### 3. 종류

#### 키-값 저장소 (Key-Value Store)

키(Key)와 값(Value)을 쌍으로 저장한다. 키를 주면 거기 연결된 값을 돌려주는 단순한 구조다. Redis, Riak, DynamoDB 등이 있다.

```css
{
  "user123": { "name": "Alice", "age": 30, "location": "NYC" }
}
```

#### 문서 저장소 (Document Store)

JSON, BSON, XML 같은 문서 형태로 저장한다. 문서마다 고유 ID가 있고, 필드와 구조가 자유로워서 여러 형식을 담을 수 있다. MongoDB, CouchDB 등이 있다.

```css
{
  "user_id": "123",
  "name": "Alice",
  "orders": [
    { "order_id": "456", "total": 50.0 },
    { "order_id": "789", "total": 75.0 }
  ]
}
```

#### 열 기반 저장소 (Column-Family Store)

행(Row)과 열(Column)로 저장하는데, 행마다 서로 다른 열을 가질 수 있다. 데이터는 행 단위로 묶여 열 패밀리(Column Family) 안에 저장된다. Cassandra, HBase 등이 있다.

```css
Row Key: user123
- Personal Data: { Name: "Alice", Age: 30 }
- Order Data: { OrderID: "456", Total: 50.0 }
```

#### 그래프 데이터베이스 (Graph Database)

데이터(노드)와 데이터 사이의 관계(엣지)를 그래프로 표현한다. 복잡한 관계를 표현하기 쉬워서 소셜 네트워크나 추천 시스템처럼 관계가 중요한 데이터에 잘 맞는다. Neo4j, Amazon Neptune 등이 있다.

```css
(Alice) -[Friend]-> (Bob)
```

---

### 4. 장점

- 확장성: 노드를 추가하는 수평 확장으로 데이터가 많아져도 성능을 끌어올릴 수 있다.
- 유연한 데이터 모델: RDBMS처럼 스키마를 엄격하게 정할 필요가 없어서 요구사항이 바뀌어도 대응이 쉽다.
- 고가용성: 데이터가 여러 노드에 나눠 저장되니 노드 하나가 죽어도 데이터에 접근할 수 있다.
- 빅데이터 처리: 대량의 데이터와 실시간 데이터를 빠르게 처리하도록 만들어졌다.

### 5. 단점

- 일관성 보장이 어렵다: ACID 트랜잭션을 완벽하게 지원하지 않아서, 특히 복제된 데이터끼리 일관성을 맞추기 힘들 수 있다.
- 쿼리가 제한적이다: RDBMS보다 복잡한 쿼리를 짜기 어렵고 JOIN을 지원하지 않는 경우가 많다. 복잡한 연산은 애플리케이션 쪽에서 따로 처리해야 할 수 있다.
- 보안과 표준화: RDBMS보다 보안 기능이 부족한 편이고, 종류가 제각각이라 SQL 같은 표준 쿼리 언어나 공통 인터페이스가 없다.

---

### 6. 어디에 쓰나

- 실시간 데이터 처리: 실시간 로그 분석이나 트래픽이 많은 웹 애플리케이션
- 대용량 데이터 저장: SNS, IoT 데이터, 추천 시스템처럼 데이터가 많이 쌓이고 빠르게 처리해야 하는 경우
- 빠른 읽기/쓰기: 읽기와 쓰기가 빨라야 하는 애플리케이션
