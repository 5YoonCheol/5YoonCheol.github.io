로그를 모아서 보고 싶을 때 많이 듣게 되는 게 ELK 스택이다. Elastic이라는 회사에서 만들고 관리하는 오픈소스 도구 묶음으로, 데이터를 모으고, 저장하고, 분석하고, 시각화하는 데 쓴다.

ELK는 아래 세 도구의 앞 글자를 딴 이름이다.

### Elasticsearch: 저장하고 검색하기

분산형 검색/분석 엔진이다. 정형이든 비정형이든 데이터를 빠르게 저장하고 검색할 수 있다. 로그, 메트릭, 문서 같은 데이터를 실시간으로 색인하고, RESTful API로 쿼리를 날려서 분석한다.

### Logstash: 모으고 가공하기

데이터 수집과 처리 파이프라인이다. 서버 로그, 애플리케이션 로그, 메트릭, CSV 파일 같은 여러 곳에서 데이터를 받아서 필터링하고 변환한 다음 Elasticsearch로 넘긴다. 플러그인 구조라서 입력, 필터, 출력을 골라 붙일 수 있다.

### Kibana: 보여주기

Elasticsearch에 쌓인 데이터를 검색하고 대시보드로 시각화하는 도구다. 차트, 그래프, 지도 같은 걸로 데이터를 한눈에 볼 수 있고, 실시간 모니터링 화면을 만들 때도 쓴다.

---

### ELK에서 Elastic Stack으로

요즘은 ELK에 도구가 몇 개 더 붙어서 Elastic Stack이라고 부르기도 한다.

- Beats: 가벼운 데이터 전송 에이전트. 서버나 애플리케이션에 붙어서 데이터를 모아 Logstash나 Elasticsearch로 보낸다. 로그를 모으는 Filebeat, 시스템 메트릭을 모으는 Metricbeat 등이 있다.
- APM(Application Performance Monitoring): 애플리케이션 성능 데이터를 모아서 어디가 느린지 분석한다.
- Elastic Security: 보안 데이터를 분석하고 침해를 탐지한다.

---

### 어디에 쓰나

**로그 관리**
서버, 애플리케이션, 네트워크 장비에서 나오는 로그를 실시간으로 모아서 분석한다. 오류 모니터링, 장애 원인 파악, 보안 이벤트 분석에 쓴다.

**애플리케이션 성능 모니터링(APM)**
애플리케이션 메트릭을 모아서 성능이 떨어지거나 병목이 생기는 지점을 찾는다.

**보안 / SIEM(Security Information and Event Management)**
보안 위협과 이상 활동을 탐지하고, 규제 요건을 맞추기 위해 로그를 보관한다.

**비즈니스 데이터 분석**
사용자 활동 로그, 클릭 데이터, 매출 기록을 분석해서 의사 결정에 참고한다.

---

### 장단점

오픈소스라 비용 부담이 적고 입맛대로 고칠 수 있다. 대량의 데이터를 처리하도록 만들어졌고, 여러 형태의 데이터를 한곳에 모아 분석할 수 있다. Kibana 덕분에 데이터를 눈으로 보기도 쉽다.

대신 이런 점은 감안해야 한다.

- 구성 요소를 전부 설정하고 관리하려면 꽤 알아야 할 게 많다.
- 데이터와 트래픽이 많아지면 하드웨어도 많이 필요하다.
- 기본 보안 설정이 최소한이라 따로 구성해줘야 한다.

---

### 설치하고 써보는 순서

1. 환경 준비: 서버나 클라우드에 띄운다. Docker를 쓰면 빨리 올릴 수 있다.
2. Elasticsearch 설치: 저장과 색인을 맡을 엔진을 설정한다.
3. Logstash 설정: 어디서 데이터를 받아 어떻게 가공할지 정한다.
4. Kibana 구성: 시각화와 대시보드를 설정한다.
5. 데이터 보내기: Beats나 Logstash로 데이터를 흘려보낸다.

---

로그 관리, 성능 모니터링, 보안 분석처럼 데이터를 대량으로 모아서 봐야 하는 일이라면 ELK 스택은 한 번쯤 검토해볼 만한 선택지다.
