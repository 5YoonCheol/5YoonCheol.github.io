Apache Kafka는 대량의 데이터 흐름(스트림)을 실시간으로 받아서 처리할 수 있는 분산 스트리밍 플랫폼이다. 메시징 시스템으로도 많이 쓰고, 데이터 파이프라인이나 실시간 분석 쪽에서 자주 등장한다. 많은 데이터를 빠르고 안정적으로 넘겨주는 데 강점이 있다.

---

### 1. 기본 개념

Kafka를 이해하려면 먼저 용어 몇 개를 알아야 한다.

- 프로듀서(Producer): Kafka로 데이터를 보내는 쪽. 데이터를 특정 토픽(Topic)으로 보낸다.
- 컨슈머(Consumer): 토픽에서 데이터를 읽어 가는 쪽. 하나 이상의 토픽을 구독하고 있다가 새 데이터가 들어오면 처리한다.
- 브로커(Broker): 데이터를 저장하고 관리하는 Kafka 서버. 브로커 여러 대가 모여 하나의 Kafka 클러스터가 되고, 데이터를 나눠서 저장하고 처리한다.
- 토픽(Topic): 데이터를 종류별로 나눠 담는 논리적인 채널. 토픽 하나는 여러 파티션으로 나뉘고, 파티션들은 여러 브로커에 흩어져 저장된다. 파티션이 나뉘어 있으니 병렬로 처리할 수 있다.
- 파티션(Partition): 실제로 데이터가 쌓이는 곳. 순서가 있는 로그이고, 데이터가 하나 추가될 때마다 고유한 오프셋(offset)이 붙는다. 이 오프셋으로 데이터의 순서와 위치를 추적한다.

### 2. 특징

- 빠르다: 실시간 처리를 염두에 두고 만들어졌다. 내부적으로 데이터를 묶어서(배치) 보내기 때문에 네트워크와 디스크 I/O를 아끼고, 지연 시간도 짧다.
- 데이터를 잃지 않는다: 파티션에 기록된 데이터를 여러 브로커에 복제해 둔다. 장애가 나도 복구할 수 있다.
- 확장이 쉽다: 파티션과 브로커를 추가하는 식으로 수평 확장이 된다.
- 장애에 강하다: 복제본이 있으니 브로커 하나가 죽어도 다른 브로커가 이어받아서 시스템이 멈추지 않는다.

### 3. 내부 동작

큰 흐름은 프로듀서가 보낸 데이터를 토픽의 파티션에 저장하고, 컨슈머가 그걸 읽어 가는 구조다.

**데이터 기록**
프로듀서가 토픽에 데이터를 보내면 Kafka는 파티션에 순서대로 쌓고 오프셋을 붙인다. 로그 형태로 남아 있으니 나중에 다시 꺼내 볼 수 있다.

**데이터 읽기**
컨슈머는 오프셋을 기준으로 읽는다. Kafka는 읽혔다고 바로 지우지 않고 일정 기간 보관하기 때문에, 실시간으로 처리할 수도 있고 나중에 다시 처리할 수도 있다. 스트리밍이든 배치든 둘 다 쓸 수 있다는 얘기다.

**복제**
파티션 데이터는 여러 브로커에 복제된다. 주 파티션(Leader)에 기록된 데이터가 복제 파티션(Replica)에도 저장되기 때문에, 주 파티션에 문제가 생겨도 복제본으로 복구할 수 있다.

**파티셔닝과 병렬 처리**
파티션은 서로 독립적으로 처리되니 여러 파티션을 동시에 처리할 수 있다. 데이터가 많을수록 이 부분이 성능을 좌우한다.

### 4. 어디에 쓰나

대용량 데이터를 실시간으로 다뤄야 하는 곳에서 주로 쓴다.

- 데이터 파이프라인: 웹 애플리케이션의 사용자 활동 로그를 모아서 분석 시스템으로 넘기는 식으로, 데이터를 실시간으로 모아 여러 시스템에 전달한다.
- 실시간 스트리밍 분석: 금융 서비스에서 거래 데이터를 실시간으로 분석해 이상 거래를 잡아내거나 리스크를 관리하는 데 쓴다.
- 메시징: 마이크로서비스끼리 Kafka 토픽을 통해 데이터를 주고받으면 서비스 간 결합도를 낮출 수 있다.
- 로그/이벤트 수집: 여러 서버에 흩어진 로그와 이벤트를 한 곳에 모아 저장하고 분석한다. 큰 시스템에서 장애를 모니터링할 때 유용하다.

### 5. 다른 메시징 시스템과 뭐가 다른가

- 데이터 보존: 보통 메시징 시스템은 메시지를 소비하면 지워 버리는데, Kafka는 보존 기간 동안 남겨 두기 때문에 다시 처리할 수 있다.
- 처리량: 배치 전송과 수평 확장 덕분에 처리량이 높다.
- 병렬 처리: 파티션과 컨슈머 그룹을 이용해서 여러 컨슈머가 동시에 일을 나눠 할 수 있다.
- 확장성: 브로커와 파티션을 늘려서 수십억 건의 메시지도 처리할 수 있다.

### 6. 장점과 한계

확장성과 성능이 좋아서 대규모 데이터 처리에 잘 맞고, 데이터를 안전하게 보관해준다. 컨슈머 그룹이 여러 개여도 같은 데이터를 각자 독립적으로 처리할 수 있다는 점도 편하다.

한계도 있다.

- 설정과 관리가 꽤 복잡하고, 규모가 커지면 관리 부담도 커진다.
- 신뢰성을 위해 복제를 많이 할수록 디스크와 네트워크 사용량이 늘어난다.
- 지연 시간 요구가 아주 빡빡한 시스템이라면 따로 성능 튜닝이 필요할 수 있다.
