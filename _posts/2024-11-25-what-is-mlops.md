DevOps는 많이 들어봤는데 MLOps는 뭘까 싶어서 정리해봤다.

MLOps(Machine Learning Operations)는 머신러닝 모델을 만들고, 배포하고, 운영하고, 유지보수하는 과정과 도구를 묶어서 부르는 말이다. 소프트웨어 개발의 DevOps(Development + Operations) 개념을 ML 프로젝트에 가져온 거라고 보면 된다. 모델을 만드는 쪽과 운영하는 쪽 사이의 간극을 줄이고, ML 수명 주기 전체를 자동화하는 게 목표다.

---

### 핵심은 다섯 가지

- 자동화: 데이터 준비, 학습, 검증, 배포를 자동으로 돌려서 매번 같은 방식으로 반복할 수 있게 한다.
- 협업: 데이터 과학자, 엔지니어, 운영팀이 같이 일하기 편하게 만든다.
- 모니터링: 배포한 뒤에도 모델 성능을 계속 지켜보면서 데이터가 변하거나(drift) 성능이 떨어지는 걸 잡아낸다.
- 재현성: 같은 데이터로 언제든 같은 결과가 나오도록 코드, 데이터, 환경을 관리한다.
- 버전 관리: 코드뿐 아니라 데이터, 모델, 파이프라인까지 버전을 관리해서 뭐가 바뀌었는지 추적한다.

---

### 왜 따로 필요할까

일반 소프트웨어와 달리 ML 모델에는 특별한 사정이 있다.

**데이터가 전부다**
모델 품질은 데이터 품질에 크게 좌우된다. 그래서 데이터 수집, 가공, 검증이 빠질 수 없다.

**계속 손봐야 한다**
시간이 지나면 데이터 자체가 변한다(데이터 드리프트). 그래서 모델을 주기적으로 다시 학습시키거나 업데이트해야 한다.

**단계가 많다**
데이터 준비, 모델 개발, 학습, 검증, 배포, 운영까지 단계가 많아서 체계적으로 관리하지 않으면 금방 엉킨다.

---

### 구성 요소

#### 1. 데이터 엔지니어링

- 데이터 수집: 데이터 소스에서 데이터를 가져온다.
- 데이터 준비: 전처리, 정규화, 특성 공학(feature engineering) 등을 한다.
- 데이터 검증: 품질을 확인하고 이상치를 걸러낸다.

#### 2. 모델 개발

- 학습: 여러 알고리즘으로 모델을 만들고 최적화한다.
- 검증: 검증용 데이터셋으로 성능을 평가한다.
- 버전 관리: 모델 코드와 학습 데이터의 버전을 관리한다.

#### 3. 모델 배포

- 배포 방식: A/B 테스트, Canary 배포, 블루/그린 배포
- 컨테이너화: Docker, Kubernetes 등으로 모델을 패키징해서 배포한다.

#### 4. 모델 모니터링

- 성능 모니터링: 예측 정확도, 응답 시간 등을 추적한다.
- 데이터 드리프트 탐지: 새로 들어오는 데이터가 기존 데이터와 많이 다르면 경고를 띄운다.
- 실시간 알림: 이상한 동작이 보이면 알림을 보낸다.

---

### 단계별로 보면

1. 개발 단계
   - 데이터 준비와 분석
   - 모델 학습과 실험 관리
   - 모델 버전 관리
2. 배포 단계
   - 모델을 운영 환경에 배포
   - CI/CD 구성
3. 운영 단계
   - 모델 모니터링과 유지보수
   - 성능 저하, 데이터 드리프트 대응
   - 주기적인 재학습

---

### 많이 쓰는 도구

- 데이터 준비/관리: Apache Airflow, Kedro, Great Expectations
- 학습/실험 관리: MLflow, TensorBoard, Neptune
- 배포/운영: Kubernetes, Docker, Seldon Core, BentoML
- 모니터링: Prometheus, Grafana, WhyLabs

---

### 장단점

반복 작업을 자동화하니 시간이 절약되고, 과정이 일정하게 유지되니 결과도 믿을 만해진다. 데이터와 모델이 많아져도 관리할 수 있다는 것도 장점이다.

반면 여러 기술과 도구를 엮어야 해서 복잡해지고, 처음 환경을 갖추는 데 시간과 비용이 꽤 든다.

---

ML 모델을 한 번 만들고 끝낼 게 아니라 서비스로 계속 운영할 거라면, 결국 MLOps 같은 체계가 필요해질 수밖에 없겠다는 생각이 든다.
