인터넷 브라우저를 통해 특정 웹사이트에 접근할 때, 사용자(클라이언트)와 웹 서버 사이에 여러 과정이 일어난다. 이 과정은 다음과 같은 단계로 이루어지며, 각 단계에서 특정 프로토콜과 기술이 사용된다.

---

### 1. **URL 입력과 DNS 조회**

- 사용자가 브라우저에 URL을 입력하면, 브라우저는 먼저 이 URL이 가리키는 서버의 **IP 주소**를 알아내야 한다.
- 이를 위해 브라우저는 DNS 서버(Domain Name System)에 요청을 보내 URL에 해당하는 IP 주소를 조회한다.
- 만약 사용자가 자주 방문한 사이트라면, 브라우저나 운영 체제에 있는 **캐시**에서 이미 IP 주소를 가지고 있을 수 있으며, 이 경우 DNS 조회를 건너뛰고 바로 IP 주소로 접근할 수 있다.

### 2. **TCP 연결 설정**

- IP 주소가 확인되면, 브라우저는 서버와의 **TCP 연결**을 설정한다. TCP 연결은 **3-way 핸드셰이크**라 불리는 과정을 통해 이루어진다.
- 클라이언트는 서버에 **SYN** 패킷을 보내고, 서버는 이에 응답하여 **SYN-ACK** 패킷을 보낸다. 클라이언트가 다시 **ACK** 패킷을 보내면 연결이 성립된다.
- 이 연결 설정 과정은 데이터 전송의 안정성과 순서 보장을 위한 과정이다.

### 3. **SSL/TLS 핸드셰이크 (HTTPS인 경우)**

- 요청하는 URL이 **HTTPS**로 시작할 경우, TCP 연결 후 **SSL/TLS 핸드셰이크**를 추가로 진행하여 보안 연결을 설정한다.
- 클라이언트와 서버는 암호화 통신을 위한 **암호화 알고리즘**과 **인증서**를 교환하며, 이후에는 암호화된 통신이 이루어진다.
- SSL/TLS 과정에서 서버는 클라이언트에게 **인증서**를 보내고, 클라이언트는 이를 검증하여 신뢰할 수 있는 서버임을 확인한다.

### 4. **HTTP 요청 전송**

- SSL/TLS 핸드셰이크가 완료되면, 브라우저는 웹 페이지를 요청하는 **HTTP 요청**을 전송한다.
- 이 요청은 일반적으로 **GET 요청** 형식이며, 서버의 특정 리소스를 요청하는 내용을 담고 있다.
- 요청에는 **헤더**가 포함되며, 여기에는 클라이언트의 정보(예: 브라우저 종류, 언어, 쿠키 등)가 담긴다.

### 5. **서버의 HTTP 응답 처리**

- 서버는 클라이언트의 요청을 처리하고, 해당하는 웹 페이지의 데이터를 **HTTP 응답**으로 전송한다.
- 응답에는 **상태 코드**가 포함되며, 상태 코드는 요청이 성공적으로 처리되었는지 여부를 나타낸다. (예: 200 OK, 404 Not Found 등)
- 웹 페이지의 콘텐츠가 **HTML, CSS, JavaScript, 이미지** 등 여러 파일로 이루어진 경우, 브라우저는 이들을 개별적으로 요청하여 받아온다.

### 6. **브라우저의 렌더링 과정**

- 브라우저는 받은 HTML, CSS, JavaScript 파일을 해석하여 화면에 웹 페이지를 렌더링한다.
- HTML 문서를 분석해 **DOM(Document Object Model)** 트리를 생성하고, CSS 파일을 통해 스타일을 적용하며, JavaScript 코드로 상호작용 요소를 처리한다.
- 웹 페이지가 동적 콘텐츠를 포함할 경우, 추가적인 **AJAX 요청**을 통해 필요한 데이터를 서버로부터 비동기적으로 받아와 화면을 업데이트할 수 있다.

### 7. **쿠키와 세션 관리**

- 서버가 응답을 보낼 때, 클라이언트에게 **쿠키**를 전달할 수 있다. 쿠키는 사용자의 로그인 정보나 설정을 저장하여 이후의 요청에 자동으로 포함될 수 있도록 한다.
- 클라이언트가 다시 같은 웹 사이트에 접속하면 쿠키가 서버로 전달되어, 서버는 사용자의 이전 상태를 기억하거나 인증 상태를 확인할 수 있다.

### 전체 과정의 요약

1. URL 입력 → DNS 조회 → IP 주소 획득
2. TCP 연결 설정
3. SSL/TLS 핸드셰이크(HTTPS인 경우)
4. HTTP 요청 전송
5. 서버의 HTTP 응답 처리
6. 브라우저 렌더링 및 추가 요청
7. 쿠키/세션 관리
