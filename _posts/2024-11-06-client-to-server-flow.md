브라우저 주소창에 URL을 치고 엔터를 누르면 화면이 뜨기까지 클라이언트와 웹 서버 사이에서 꽤 많은 일이 일어난다. 단계별로 어떤 프로토콜과 기술이 쓰이는지 따라가 보자.

---

### 1. URL 입력과 DNS 조회

- URL을 입력하면 브라우저는 먼저 그 URL이 가리키는 서버의 IP 주소를 알아내야 한다.
- 그래서 DNS(Domain Name System) 서버에 요청을 보내서 URL에 해당하는 IP 주소를 물어본다.
- 자주 가던 사이트라면 브라우저나 운영 체제 캐시에 IP 주소가 이미 있을 수 있다. 그러면 DNS 조회 없이 바로 그 IP로 접근한다.

### 2. TCP 연결

- IP 주소를 알아내면 브라우저는 서버와 TCP 연결을 맺는다. 이걸 3-way 핸드셰이크라고 부른다.
- 클라이언트가 SYN 패킷을 보내고, 서버가 SYN-ACK으로 답하고, 클라이언트가 다시 ACK을 보내면 연결이 맺어진다.
- 데이터를 안정적으로, 순서대로 주고받기 위한 과정이다.

### 3. SSL/TLS 핸드셰이크 (HTTPS인 경우)

- URL이 HTTPS로 시작하면 TCP 연결 뒤에 SSL/TLS 핸드셰이크를 한 번 더 해서 보안 연결을 만든다.
- 클라이언트와 서버가 어떤 암호화 알고리즘을 쓸지 정하고 인증서를 주고받는다. 이후 통신은 전부 암호화된다.
- 이 과정에서 서버가 인증서를 보내면 클라이언트는 그걸 검증해서 믿을 수 있는 서버인지 확인한다.

### 4. HTTP 요청 전송

- 핸드셰이크가 끝나면 브라우저가 웹 페이지를 달라는 HTTP 요청을 보낸다.
- 보통은 GET 요청이고, 서버의 특정 리소스를 요청하는 내용이 들어 있다.
- 요청 헤더에는 브라우저 종류, 언어, 쿠키 같은 클라이언트 정보가 담긴다.

### 5. 서버의 HTTP 응답

- 서버는 요청을 처리하고 웹 페이지 데이터를 HTTP 응답으로 돌려준다.
- 응답에는 요청이 잘 처리됐는지 알려주는 상태 코드가 들어 있다. (예: 200 OK, 404 Not Found 등)
- 페이지가 HTML, CSS, JavaScript, 이미지 같은 여러 파일로 이뤄져 있으면 브라우저가 그 파일들을 하나씩 따로 요청해서 받아온다.

### 6. 브라우저 렌더링

- 브라우저는 받은 HTML, CSS, JavaScript를 해석해서 화면에 그린다.
- HTML을 분석해 DOM(Document Object Model) 트리를 만들고, CSS로 스타일을 입히고, JavaScript로 상호작용을 처리한다.
- 동적인 콘텐츠가 있으면 AJAX 요청으로 필요한 데이터를 비동기로 받아와서 화면을 갱신한다.

### 7. 쿠키와 세션

- 서버는 응답에 쿠키를 실어 보낼 수 있다. 쿠키에는 로그인 정보나 설정이 저장되고, 이후 요청에 자동으로 따라간다.
- 같은 사이트에 다시 접속하면 쿠키가 서버로 넘어가서, 서버가 사용자의 이전 상태나 로그인 여부를 알 수 있다.

### 한 줄씩 요약

1. URL 입력 → DNS 조회 → IP 주소 획득
2. TCP 연결 설정
3. SSL/TLS 핸드셰이크(HTTPS인 경우)
4. HTTP 요청 전송
5. 서버의 HTTP 응답 처리
6. 브라우저 렌더링 및 추가 요청
7. 쿠키/세션 관리
