개인정보를 다루는 시스템이라면 데이터 분리보관과 DB 마스킹(Data Masking) 얘기를 피해갈 수 없다. 둘 다 민감한 정보가 밖으로 새지 않게 막는 방법이다.

---

### 1. 데이터 분리보관 (Data Segregation)

중요한 데이터를 일반 데이터와 따로 떼어서 보관하는 방법이다. 주로 개인정보 같은 민감한 데이터를 다룰 때 쓰고, 그 데이터가 필요 없는 사용자나 시스템이 접근하지 못하게 한다.

#### 분리하는 방법

1. 물리적 분리
   - 데이터를 서로 다른 저장 장치나 서버에 저장한다. 금융 정보와 일반 사용자 정보를 아예 다른 서버나 DB에 나눠 두는 식이다.
2. 논리적 분리
   - 저장은 같은 서버나 DB에 하지만, 권한으로 나눠서 접근을 막는다. DB 레벨에서 사용자 권한과 접근 정책을 설정해 특정 데이터에 접근하지 못하게 한다.
3. 네트워크 분리
   - 민감한 데이터를 처리하는 시스템을 외부 네트워크와 완전히 떨어진 네트워크에서 돌린다. 외부 접근을 아예 원천 차단하는 거고, 망분리라고도 한다.
     ex) 전산망, 업무망, 외부망

#### 분리보관하면 좋은 점

민감한 정보에 누가 접근할 수 있는지 엄격하게 통제할 수 있다. 유출 사고가 나더라도 데이터가 나뉘어 있으니 피해 범위가 줄어든다.

---

### 2. DB 마스킹 (Data Masking)

DB에 있는 민감한 정보를 실제 값 대신 가린 값으로 바꿔서, 권한 없는 사람이 데이터를 보더라도 중요한 정보는 보이지 않게 하는 방법이다. 개인정보, 신용카드 번호, 주민등록번호 같은 데이터에 적용한다.

#### 마스킹 종류

1. 정적 마스킹 (Static Data Masking)
   - 민감한 데이터를 복사해서 마스킹된 DB를 따로 만든다. 이걸 테스트 환경에서 쓰면 실제 데이터는 건드리지 않고 테스트할 수 있다.
2. 동적 마스킹 (Dynamic Data Masking)
   - 사용자가 조회할 때 실시간으로 가려서 보여준다. DB에는 원본이 그대로 있고, 조회 결과만 가린 값으로 나간다.
3. 부분 마스킹 (Partial Data Masking)
   - 일부만 가리고 나머지는 보여준다. 전화번호 010-1234-5678을 `010-****-5678`로 보여주는 식이다.

#### 마스킹 방법

1. 문자열 마스킹
   - 민감한 문자열을 `*`, `X` 같은 의미 없는 문자로 바꾼다.
   - 예: 주민등록번호 900101-1234567 → `900101-*******`
2. 숫자 마스킹
   - 민감한 숫자를 정해진 규칙에 따라 다른 숫자로 바꾼다.
   - 예: 신용카드 번호 1234-5678-9876-5432 → `****-****-****-5432`
3. 날짜 마스킹
   - 날짜를 바꾸거나 일부만 보여준다.
   - 예: 생년월일 1990-01-01 → `1990-**-**`
4. 난수 생성
   - 데이터 자체를 랜덤한 값으로 바꿔서 실제 데이터와 아무 관련이 없게 만든다.

#### 어디에 쓰나

- 테스트 환경: 실제 데이터를 그대로 쓸 수 없는 테스트 환경에서 마스킹한 데이터로 테스트한다.
- 외부 협업: 외부 업체나 개발자가 시스템에 들어와 작업할 때 민감한 정보를 보지 않고도 일할 수 있게 한다.

#### 마스킹하면 좋은 점

DB에 접근하는 사람이 가린 데이터만 보게 되니 노출 위험이 줄어든다. 개인정보보호법, GDPR 같은 규제가 요구하는 보호 수준을 맞추는 데도 도움이 된다.

---

정리하면 데이터 분리보관은 데이터를 물리적으로든 논리적으로든 떼어놓아서 접근 자체를 막는 거고, DB 마스킹은 데이터를 보더라도 민감한 부분은 못 보게 가리는 거다. 개인정보를 다룬다면 둘 다 챙겨야 한다.
