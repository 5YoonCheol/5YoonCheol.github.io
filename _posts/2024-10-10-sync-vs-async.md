동기와 비동기는 프로그램이 작업을 어떤 순서로, 어떻게 처리하느냐에 대한 개념이다. 어느 쪽을 쓰느냐에 따라 프로그램 동작이 꽤 달라진다. 오늘은 둘의 차이를 알아보자.

---

### 1. 동기(Synchronous) 방식

작업을 순서대로 처리한다. 하나가 끝나야 다음 작업이 시작되고, 그 전까지 프로그램은 다음 단계로 넘어가지 않는다. 실행 순서가 분명하니 흐름을 따라가기 쉽다.

```java
System.out.println("First Task Started");
Thread.sleep(2000); // 2초간 대기
System.out.println("Second Task Started");
```

첫 번째 출력문이 실행되고 `Thread.sleep(2000);`이 호출되면 2초 동안 아무것도 진행되지 않는다. 2초가 지나야 두 번째 출력문이 실행된다.

#### 장점

순서대로 처리되니 코드 흐름이 눈에 잘 들어온다. 디버깅도 쉽다. 차례대로 진행되니 어디서 문제가 났는지 찾기 편하다.

#### 단점

비효율적이다. 네트워크 요청이나 파일 I/O처럼 오래 걸리는 작업이 있으면 그게 끝날 때까지 기다려야 해서 프로그램이 멈춘 것처럼 보일 수 있다. 기다리는 동안 다른 일을 못 하니 자원도 낭비된다.

---

### 2. 비동기(Asynchronous) 방식

작업이 끝나기를 기다리지 않고 다른 작업을 동시에 시작하는 방식이다. 프로그램이 멈추지 않고 여러 일을 같이 처리할 수 있다. 네트워크 요청, 파일 읽기/쓰기, DB 접근처럼 시간이 걸리는 작업에서 특히 쓸모가 있다.

```java
System.out.println("First Task Started");

new Thread(() -> {
    try {
        Thread.sleep(2000); // 2초간 대기
        System.out.println("Second Task Completed");
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
}).start();

System.out.println("Third Task Started");
```

새 스레드를 만들어서 `Thread.sleep(2000);`을 비동기로 돌린다. sleep이 도는 동안에도 메인 스레드는 `System.out.println("Third Task Started");`를 바로 실행한다. 그래서 첫 번째, 세 번째, 두 번째 작업 순으로 실행될 수 있다.

#### 장점

오래 걸리는 작업이 있어도 다른 작업을 같이 처리하니 프로그램 응답이 빠르다. 기다리는 동안 다른 일을 하니 CPU나 메모리 같은 자원도 알뜰하게 쓴다.

#### 단점

- 여러 작업이 순서 없이 돌아가니 코드 흐름을 파악하기 어렵다.
- 비동기 작업 중에 오류가 나면 어디서 났는지 찾기 힘들다.
- 레이스 컨디션 같은 문제가 생기기 쉽다. 여러 작업이 동시에 공유 자원에 접근하면 서로 간섭해서 예상 못 한 결과가 나올 수 있다.

---

### 언제 무엇을 쓰나

동기 방식은 DB 트랜잭션처럼 순서대로 처리해야 하는 작업에 맞다. 트랜잭션은 모든 작업이 순서대로 일어나야 하고, 이전 단계가 끝나야 다음 단계로 넘어갈 수 있다.

비동기 방식은 네트워크 요청, 대용량 파일 처리, UI 이벤트 처리에 자주 쓴다. 웹 애플리케이션에서 네트워크 요청을 비동기로 보내면 서버 응답을 기다리는 동안 다른 작업을 할 수 있다.

### 섞어서 쓰기

실제 프로그램은 대부분 둘을 섞어 쓴다. 핵심 흐름은 동기로 처리하고, 백그라운드 작업이나 오래 걸리는 작업은 비동기로 돌리는 식이다. Java에서는 CompletableFuture, ExecutorService, Java NIO 같은 걸로 비동기 처리를 구현할 수 있다.

둘의 차이를 알고 상황에 맞게 섞어 쓰면 응답도 빠르고 안정적인 애플리케이션을 만들 수 있다.
