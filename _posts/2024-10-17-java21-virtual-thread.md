Java 21에서 정식 기능이 된 가상 쓰레드(Virtual Thread)를 정리해보려고 한다.

가상 쓰레드는 기존 플랫폼 쓰레드(Platform Thread)보다 훨씬 가볍게 동시성을 처리할 수 있게 해주는 기능이다. Java 19에서 프리뷰로 먼저 나왔고, Java 21에서 정식으로 들어왔다. 동시 요청이 많은 애플리케이션이라면 성능 차이를 크게 볼 수 있다.

---

### 1. 가상 쓰레드란?

JVM이 직접 관리하는 경량 쓰레드다. 기존 플랫폼 쓰레드는 OS 쓰레드와 1:1로 묶여 있어서 만들고 관리하는 데 자원이 많이 들었다. 가상 쓰레드는 JVM이 관리하기 때문에 OS 쓰레드를 일일이 잡아먹지 않고도 수천, 수만 개를 한꺼번에 만들어 돌릴 수 있다.

블로킹 작업을 만나면 JVM이 알아서 처리해주는 게 핵심이다. 그래서 I/O 바운드 작업에서 특히 유용하다. 보통은 쓰레드가 많이 블로킹되면 그만큼 자원이 놀게 되는데, 가상 쓰레드는 대기 중일 때 OS 쓰레드를 내려놓기 때문에 자원을 낭비하지 않는다.

### 2. 특징

- 가볍다: OS 쓰레드 자원을 직접 쓰지 않아서 수천 개를 만들어도 성능이 떨어지지 않고 메모리도 훨씬 적게 쓴다.
- 블로킹 코드를 그대로 쓴다: 예전엔 성능 때문에 비동기 프로그래밍을 해야 했지만, 가상 쓰레드에서는 동기식 코드로 블로킹 I/O를 처리해도 된다. 코드가 읽기 쉽고 유지보수하기 편하다.
- 스케줄링을 JVM이 한다: 대기 중인 가상 쓰레드는 OS 쓰레드를 차지하지 않도록 JVM이 알아서 스케줄링한다.
- 기존 쓰레드와 같이 쓸 수 있다: 플랫폼 쓰레드와 섞어 쓸 수 있어서 기존 코드와 호환이 잘 된다.

### 3. 사용 예시

Thread.ofVirtual().start()로 간단하게 만들 수 있다. 기존 쓰레드 만드는 방식과 거의 같고, 실행할 작업을 람다로 넘기면 된다.

```java
Runnable task = () -> {
    // 실행할 작업 코드
    System.out.println("Hello from virtual thread!");
};

Thread virtualThread = Thread.ofVirtual().start(task);
```

대규모 동시성이 필요한 애플리케이션에서 특히 쓸모가 있다.

예를 들어 웹 서버에서 클라이언트 요청 하나하나를 가상 쓰레드에 맡기면, 서버 부담은 줄이면서 대량의 요청을 처리할 수 있다.

### 4. 내부 동작

가상 쓰레드는 JVM이 관리하는 쓰레드 풀 위에서 돈다. 실제로 일을 하는 건 플랫폼 쓰레드이고, 가상 쓰레드는 플랫폼 쓰레드에 올라타야 실행된다. 작업이 블로킹되면 가상 쓰레드는 플랫폼 쓰레드에서 내려오고, 블로킹이 풀리면 다시 플랫폼 쓰레드에 올라가서 이어서 실행된다.

- 파이버(Fiber)처럼 동작해서 컨텍스트 스위칭이 OS가 아니라 JVM 안에서 일어난다. 그래서 쓰레드 전환에 드는 메모리와 CPU 비용이 줄어든다.
- 플랫폼 쓰레드보다 작은 스택으로 시작하고 필요할 때 늘린다. 메모리를 아껴 쓰는 방식이다.

### 5. 장점과 한계

좋은 점은 쓰레드를 아주 많이 띄워도 가볍기 때문에 동시성 처리 성능이 크게 좋아진다는 거다. 비동기 코드 대신 동기식 블로킹 코드로 짤 수 있어서 읽기 쉽고, 기존 플랫폼 쓰레드와도 같이 쓸 수 있다.

한계도 있다.

- CPU를 많이 쓰는 작업에서는 플랫폼 쓰레드와 성능 차이가 크지 않고, 오히려 부담이 늘 수 있다.
- JVM이 스케줄링하는 방식이라 모든 상황에 최적은 아니다.
- 플랫폼 쓰레드 기반의 저수준 시스템 호출과는 같이 쓰기 어렵다.

### 6. 기존 쓰레드와 비교

- 성능: 가상 쓰레드는 메모리와 CPU를 적게 써서 동시 처리량이 많은 작업에 잘 맞는다.
- 가독성: 블로킹 I/O를 동기식으로 처리할 수 있어서 비동기 코드보다 이해하기 쉽다.
- 호환성: 플랫폼 쓰레드와 같이 쓸 수 있고, 기존 동기 메서드와 API를 그대로 쓸 수 있다.
