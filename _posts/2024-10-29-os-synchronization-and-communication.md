### 1. 동기화 (Synchronization)

동기화는 **여러 프로세스나 스레드가 동시에 작업을 수행할 때 데이터의 일관성을 유지하기 위한 메커니즘**이다.

특히, 다수의 스레드나 프로세스가 같은 자원(메모리, 파일 등)에 접근하려고 할 때, 데이터의 무결성을 보장하기 위해 동기화가 필요하다.

#### **동기화의 필요성**

- **데이터 일관성 유지**: 여러 스레드가 동시에 자원에 접근하면, 예측하지 못한 결과가 발생할 수 있다. 예를 들어, 은행 계좌 잔액을 동시에 업데이트하는 경우, 동기화를 하지 않으면 잔액이 잘못 계산될 수 있다.
- **데이터 레이스(Data Race) 방지**: 다중 스레드가 같은 자원에 동시에 접근해 데이터를 변경하는 경우, 데이터 레이스가 발생할 수 있으며, 결과는 예측 불가능하게 된다.
- **교착 상태(Deadlock) 예방**: 서로 다른 스레드가 자원을 기다리며 무한 대기에 빠지지 않도록 동기화는 자원에 대한 접근 순서를 조정한다.

#### **동기화 기법**

1. **뮤텍스 (Mutex, Mutual Exclusion)**: 하나의 스레드만 자원에 접근할 수 있도록 제한하는 방식이다. 스레드가 자원을 사용 중이면 뮤텍스를 잠그고, 다른 스레드는 잠금을 해제할 때까지 기다린다. 자원이 해제되면 다음 대기 중인 스레드가 자원에 접근한다.
2. **세마포어 (Semaphore)**: 자원에 접근할 수 있는 스레드의 수를 제한한다. 예를 들어, 특정 자원에 두 개의 스레드만 접근이 가능하다면 세마포어를 2로 설정하고, 두 개의 스레드가 접근할 때까지 다른 스레드는 대기한다.
3. **모니터 (Monitor)**: 특정 언어에서 제공하는 동기화 도구로, 자원의 접근을 모니터 객체를 통해 제어한다. 자원의 일관성을 보장하기 위해 내부에서 스레드가 작업을 완료할 때까지 잠금을 제공한다. 예를 들어, Java에서 synchronized 키워드는 모니터를 활용한다.
4. **락 (Lock)**: 뮤텍스와 유사하지만, 락은 좀 더 다양한 기능을 제공한다. 예를 들어, 락의 재진입 가능 여부나, 특정 조건에서 락을 걸지 않는 선택적인 락 사용 등이 있다.

#### **동기화 예시**

- **은행 잔액 처리**: 여러 스레드가 한 사용자의 계좌 잔액을 동시에 읽고 업데이트하면 동기화 문제가 발생할 수 있다. 이때, 잔액 업데이트 연산은 뮤텍스나 세마포어를 통해 동기화한다.
- **파일 쓰기 작업**: 두 개의 프로세스가 동시에 같은 파일에 데이터를 쓰면 데이터가 꼬일 수 있다. 파일을 잠금(lock) 상태로 두어 하나의 프로세스만 파일에 접근하도록 한다.

### 2. 통신 (Communication)

통신은 **프로세스 간 또는 스레드 간에 정보를 주고받기 위한 방법**이다. 서로 다른 프로세스는 메모리를 공유하지 않기 때문에 별도의 통신 방식이 필요하며, 스레드 간 통신은 메모리와 변수를 공유하므로 주로 동기화를 통해 이루어진다.

#### **프로세스 간 통신(IPC, Inter-Process Communication) 방법**

1. **파이프 (Pipe)**: 한 프로세스에서 다른 프로세스로 데이터를 보내는 통신 방법이다. 단방향 또는 양방향으로 사용 가능하며, 주로 부모-자식 프로세스 간에 사용된다. 파이프는 운영체제에서 제공하는 메모리 공간을 사용해 데이터를 전달한다.
2. **메시지 큐 (Message Queue)**: 여러 프로세스가 메시지를 보낼 수 있는 큐를 형성하여 통신하는 방식이다. 비동기식으로 작동하며, 하나의 프로세스가 메시지를 큐에 넣으면 다른 프로세스가 이 메시지를 가져갈 수 있다.
3. **공유 메모리 (Shared Memory)**: 여러 프로세스가 같은 메모리 공간을 공유하여 데이터를 교환하는 방식이다. 메모리를 공유하기 때문에 빠른 통신이 가능하지만, 동기화 문제를 해결해야 한다.
4. **소켓 (Socket)**: 네트워크를 통해 데이터를 주고받기 위한 방식으로, 주로 서로 다른 컴퓨터 간의 통신에 사용된다. 소켓은 TCP/IP 프로토콜을 사용해 연결된 두 시스템 간의 통신을 제공한다.
5. **시그널 (Signal)**: 간단한 메시지나 이벤트 알림을 보내기 위한 방식이다. 주로 프로세스의 상태 변화를 알리거나 프로세스를 종료하는 데 사용된다.

#### **스레드 간 통신 방법**

스레드는 같은 프로세스 내에서 자원을 공유하기 때문에 주로 **공유 메모리와 변수**를 사용하여 통신한다. 하지만, 스레드 간 통신 시에도 자원 충돌이나 동기화 문제가 발생할 수 있으므로 적절한 동기화 기법(뮤텍스, 세마포어 등)이 필요하다.

#### 통신의 예시

- **메시지 큐를 통한 채팅**: 채팅 애플리케이션에서는 메시지 큐를 사용하여 메시지를 전송하고 다른 사용자에게 전달한다.
- **공유 메모리를 이용한 계산 작업 분할**: 여러 프로세스가 계산 작업을 나누어 수행할 때, 계산 결과를 공유 메모리에 저장하여 전체 결과를 계산하는 데 사용할 수 있다.
- **소켓 통신을 이용한 웹 서버**: 웹 서버는 클라이언트와 서버 간의 통신에 소켓을 사용하여 데이터를 주고받는다.
