지난번 프로세스와 스레드에 이어서, 이번엔 이것들이 같이 일할 때 필요한 동기화와 통신을 정리해보자.

### 1. 동기화 (Synchronization)

동기화는 여러 프로세스나 스레드가 동시에 일할 때 데이터가 꼬이지 않게 해주는 장치다.

여러 스레드나 프로세스가 같은 자원(메모리, 파일 등)에 동시에 손을 대면 데이터가 엉망이 될 수 있다. 이걸 막으려고 동기화를 한다.

#### 왜 필요한가

- 데이터 일관성: 여러 스레드가 동시에 같은 자원에 접근하면 예상 못 한 결과가 나온다. 예를 들어 같은 은행 계좌 잔액을 동시에 업데이트하면 잔액이 잘못 계산될 수 있다.
- 데이터 레이스(Data Race) 방지: 여러 스레드가 같은 데이터를 동시에 바꾸면 결과를 예측할 수 없게 된다.
- 교착 상태(Deadlock) 예방: 스레드들이 서로 상대가 가진 자원을 기다리며 끝없이 멈춰 버리지 않도록 접근 순서를 조정한다.

#### 동기화 기법

1. 뮤텍스 (Mutex, Mutual Exclusion): 한 번에 하나의 스레드만 자원을 쓰게 한다. 자원을 쓰는 스레드가 뮤텍스를 잠그면, 다른 스레드는 잠금이 풀릴 때까지 기다렸다가 차례로 들어간다.
2. 세마포어 (Semaphore): 자원에 동시에 들어갈 수 있는 스레드 수를 제한한다. 예를 들어 세마포어를 2로 두면 두 개까지만 들어가고 나머지는 기다린다.
3. 모니터 (Monitor): 언어 차원에서 제공하는 동기화 도구다. 모니터 객체를 통해 자원 접근을 제어하고, 안에서 작업이 끝날 때까지 잠금을 걸어준다. Java의 synchronized 키워드가 모니터를 쓴다.
4. 락 (Lock): 뮤텍스와 비슷하지만 기능이 더 다양하다. 같은 스레드가 다시 들어올 수 있는지(재진입), 특정 조건에서만 잠글지 같은 걸 선택할 수 있다.

#### 예시

- 은행 잔액 처리: 여러 스레드가 한 계좌의 잔액을 동시에 읽고 쓰면 문제가 생긴다. 잔액을 바꾸는 부분은 뮤텍스나 세마포어로 묶어준다.
- 파일 쓰기: 두 프로세스가 같은 파일에 동시에 쓰면 내용이 섞일 수 있다. 파일에 잠금(lock)을 걸어서 한 번에 한 프로세스만 쓰게 한다.

### 2. 통신 (Communication)

통신은 프로세스나 스레드끼리 정보를 주고받는 방법이다. 프로세스는 서로 메모리를 공유하지 않아서 따로 통신 수단이 필요하고, 스레드는 메모리와 변수를 공유하니 주로 동기화를 곁들여서 주고받는다.

#### 프로세스 간 통신(IPC, Inter-Process Communication)

1. 파이프 (Pipe): 한 프로세스에서 다른 프로세스로 데이터를 흘려보낸다. 단방향이나 양방향으로 쓸 수 있고, 주로 부모-자식 프로세스 사이에서 쓴다. OS가 제공하는 메모리 공간을 통해 데이터를 넘긴다.
2. 메시지 큐 (Message Queue): 큐에 메시지를 넣고 빼는 방식이다. 비동기로 동작해서, 한 프로세스가 메시지를 넣어 두면 다른 프로세스가 나중에 꺼내 간다.
3. 공유 메모리 (Shared Memory): 여러 프로세스가 같은 메모리 영역을 같이 쓴다. 제일 빠르지만 동기화 문제를 직접 해결해야 한다.
4. 소켓 (Socket): 네트워크로 데이터를 주고받는다. 주로 서로 다른 컴퓨터끼리 통신할 때 쓰고, TCP/IP 위에서 동작한다.
5. 시그널 (Signal): 간단한 알림을 보낸다. 프로세스 상태 변화를 알리거나 프로세스를 종료시킬 때 주로 쓴다.

#### 스레드 간 통신

스레드는 같은 프로세스 안에서 자원을 공유하니까 보통 공유 메모리와 변수로 주고받는다. 다만 이때도 충돌이 생길 수 있어서 뮤텍스나 세마포어 같은 동기화가 같이 필요하다.

#### 예시

- 메시지 큐로 채팅: 채팅 앱에서 메시지를 큐에 넣어 다른 사용자에게 전달한다.
- 공유 메모리로 계산 나누기: 여러 프로세스가 계산을 나눠 하고, 결과를 공유 메모리에 모아 최종 결과를 낸다.
- 소켓으로 웹 서버: 웹 서버는 클라이언트와 소켓으로 데이터를 주고받는다.
