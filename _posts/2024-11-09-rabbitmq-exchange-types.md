비동기 메시징에서 Exchange 타입은 메시지를 어떤 방식으로 전달할지 정하는 설정이다.

RabbitMQ나 Apache Kafka 같은 메시지 브로커를 쓸 때, 메시지를 여러 소비자에게 나눠 보내거나 조건에 맞는 곳에만 보내려면 이걸 알아야 한다.

정확히는 교환기(Exchange)가 받은 메시지를 어느 큐(Queue)로 보낼지, 그 라우팅 전략을 정하는 거다.

RabbitMQ의 Exchange 타입을 예로 알아보자.

---

### 1. Direct Exchange

- 라우팅 키를 기준으로 메시지를 보낸다.
- 메시지에 라우팅 키를 붙여 보내면, 그 키와 일치하는 큐만 메시지를 받는다.
- 예를 들어 주문 시스템에 "error"와 "info" 라우팅 키를 가진 큐가 있으면, "error" 키가 붙은 메시지는 error 큐로만 간다.
- 1:1이나 1:N으로 특정 대상에게만 메시지를 보낼 때 쓴다.

### 2. Fanout Exchange

- 연결된 모든 큐에 메시지를 브로드캐스트한다.
- 라우팅 키는 무시하고 바인딩된 큐 전부에 보내니 모든 큐가 같은 메시지를 받는다.
- 공지사항, 방송 알림처럼 모든 구독자에게 같은 메시지를 보낼 때 맞다.
- 1:N으로 모든 소비자에게 한꺼번에 보내야 할 때 쓴다.

### 3. Topic Exchange

- 패턴 매칭으로 라우팅한다. 라우팅 키가 큐에 설정된 패턴과 맞으면 그 큐로 간다.
- 라우팅 키는 마침표로 구분한 단어들로 이뤄지고, `*`(한 단어 일치)와 `#`(여러 단어 일치) 같은 와일드카드를 쓸 수 있다.
- 예를 들어 `log.*` 패턴으로 바인딩된 큐는 `log.error`, `log.info` 같은 라우팅 키의 메시지를 받는다.
- 주제나 범주별로 메시지를 나눠 보낼 때 쓴다.

### 4. Headers Exchange

- 라우팅 키 대신 헤더 정보를 보고 라우팅한다.
- 메시지에 헤더 속성을 넣고, 큐에도 헤더 조건을 걸어두면 조건이 맞는 메시지만 받는다.
- 예를 들어 헤더에 `department: sales`와 `type: report`가 있는 메시지는 이 조건을 걸어둔 큐에서만 받는다.
- 라우팅 키가 아니라 속성이나 메타데이터를 기준으로 보내고 싶을 때 쓴다.

### 한눈에 보기

| Exchange 타입 | 주요 기능 | 사용 사례 |
| --- | --- | --- |
| Direct Exchange | 특정 라우팅 키를 가진 큐에 전달 | 특정 서비스나 모듈에만 메시지 전달 |
| Fanout Exchange | 연결된 모든 큐에 브로드캐스트 | 이벤트 알림, 공지사항 전송 |
| Topic Exchange | 패턴에 따라 메시지를 라우팅 | 주제별 메시지 구독 시스템 |
| Headers Exchange | 헤더 조건에 맞는 큐에 메시지 전달 | 특정 조건을 만족하는 데이터 처리 |
