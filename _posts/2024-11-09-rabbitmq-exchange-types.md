비동기 메시징에서 **Exchange 타입**은 메시지를 전달할 때 어떤 방식으로 전달할지 결정하는 역할을 한다.

일반적으로 **메시지 브로커**(예: RabbitMQ, Apache Kafka 등)를 사용할 때, 메시지를 여러 소비자에게 라우팅하거나 특정 조건에 따라 필터링해서 전달하는 데 중요한 요소이다.

Exchange 타입은 메시지를 교환기(Exchange)에서 큐(Queue)로 전달할 때 라우팅 전략을 설정하는 방법을 의미한다.

예시로 RabbitMQ의 Exchange 타입에 대해 알아보자.

---

### 1. **Direct Exchange**

- Direct Exchange는 메시지를 **특정 라우팅 키**를 기준으로 라우팅한다.
- 메시지를 보낼 때 특정 라우팅 키를 설정하고, 큐도 해당 키와 일치하는 경우에만 메시지를 수신한다.
- 예를 들어, 주문 시스템에서 “error”와 “info”라는 두 개의 라우팅 키를 가진 큐가 있을 때, “error” 라우팅 키를 가진 메시지는 error 큐로만 전달된다.
- **특징**: 1:1 또는 1:N 방식으로 특정 대상에게만 메시지를 보내는 경우 유용하다.

### 2. **Fanout Exchange**

- Fanout Exchange는 **모든 연결된 큐에 메시지를 브로드캐스트** 방식으로 전달한다.
- 라우팅 키를 무시하고, 메시지를 바인딩된 모든 큐로 보내기 때문에 각 큐가 메시지를 동일하게 받는다.
- 예를 들어, 공지사항, 방송 알림 등 모든 구독자에게 동일한 메시지를 전달하는 상황에 적합하다.
- **특징**: 1:N 방식으로 모든 소비자에게 메시지를 동시에 전달해야 할 때 적합하다.

### 3. **Topic Exchange**

- Topic Exchange는 **패턴 매칭 기반의 라우팅**을 지원하는 방식으로, 메시지의 라우팅 키가 특정 패턴에 맞는 큐에 메시지를 전달한다.
- 라우팅 키는 마침표로 구분된 단어들로 구성되며, `*`(한 단어 일치)와`#`(여러 단어 일치)와 같은 와일드카드를 사용할 수 있다.
- 예를 들어, `log.*` 패턴으로 바인딩된 큐는 `log.error`나 `log.info` 같은 라우팅 키가 있는 메시지만 수신한다.
- **특징**: 특정 주제나 범주에 따라 메시지를 분류하고 전달할 때 유용하다.

### 4. **Headers Exchange**

- Headers Exchange는 라우팅 키 대신 **헤더 정보**를 기반으로 라우팅하는 방식이다.
- 메시지의 헤더 속성을 설정하고, 각 큐도 헤더 조건을 설정하여 조건이 일치하는 메시지만 수신한다.
- 예를 들어, 헤더에 `department: sales`와 `type: report`가 포함된 메시지라면, 이를 조건으로 설정한 큐에서만 수신한다.
- **특징**: 라우팅 키가 아닌 특정 속성이나 메타데이터를 기준으로 메시지를 라우팅할 때 유용하다.

---

### 주요 Exchange 타입별 사용 사례

| ***Exchange 타입*** | ***주요 기능*** | ***사용 사례*** |
| --- | --- | --- |
| Direct Exchange | 특정 라우팅 키를 가진 큐에 전달 | 특정 서비스나 모듈에만 메시지 전달 |
| Fanout Exchange | 연결된 모든 큐에 브로드캐스트 | 이벤트 알림, 공지사항 전송 |
| Topic Exchange | 패턴에 따라 메시지를 라우팅 | 주제별 메시지 구독 시스템 |
| Headers Exchange | 헤더 조건에 맞는 큐에 메시지 전달 | 특정 조건을 만족하는 데이터 처리 |
