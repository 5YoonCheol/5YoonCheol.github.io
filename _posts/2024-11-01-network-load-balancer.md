### 로드 밸런서 (Load Balancer)란?

로드 밸런서는 서버나 네트워크의 부하를 분산하는 장치 또는 소프트웨어로, **서버에 가해지는 트래픽을 여러 서버로 분배하여 시스템의 성능을 최적화**하고, **응답 속도를 향상**시키며 **가용성을 보장**한다. 이를 통해 서비스의 안정성과 확장성을 유지하고, 클라이언트 요청을 가장 적절한 서버로 전달할 수 있다.

---

### 로드 밸런서의 작동 방식

로드 밸런서는 **클라이언트가 요청을 보내면 이를 여러 서버에 고르게 분산**시켜 최적의 성능을 유지한다. 이를 위해 다양한 분산 알고리즘을 사용하여 각 서버의 상태를 모니터링하고, 부하가 적은 서버 또는 응답 속도가 가장 빠른 서버에 요청을 전달한다.

로드 밸런서는 네트워크 계층 또는 애플리케이션 계층에서 동작할 수 있으며, **L4** 또는 **L7 로드 밸런서**라고 불린다.

---

### 로드 밸런싱 알고리즘

1. **라운드 로빈 (Round Robin)**: 모든 서버에 순서대로 요청을 분배하는 방식이다. 간단하지만 각 서버의 부하 상태를 고려하지 않기 때문에 서버 간의 성능 차이가 클 경우 문제가 발생할 수 있다.
2. **가중치 라운드 로빈 (Weighted Round Robin)**: 각 서버에 가중치를 부여하고, 가중치가 높은 서버에 더 많은 요청을 할당하는 방식이다. 서버의 처리 능력 차이가 있을 때 효과적이다.
3. **최소 연결 방식 (Least Connections)**: 현재 연결 수가 가장 적은 서버에 요청을 전달한다. 서버 부하 상태에 따라 유동적으로 요청을 할당할 수 있다.
4. **IP 해싱 (IP Hashing)**: 클라이언트의 IP 주소를 해싱하여 특정 서버에 요청을 할당한다. 이 방식은 클라이언트가 항상 동일한 서버에 연결될 수 있어 상태 유지가 필요한 서비스에 유용하다.
5. **응답 시간 기반 (Response Time-Based)**: 서버의 응답 시간을 모니터링하고, 응답 시간이 가장 빠른 서버에 요청을 전달한다.

---

### L4와 L7 로드 밸런서

로드 밸런서는 OSI 7 계층 중 4계층 또는 7계층에서 주로 동작하며, 계층에 따라 동작 방식과 기능이 다르다.

- **L4 로드 밸런서 (네트워크 계층)**: 전송 계층의 IP 주소와 포트 번호를 기준으로 트래픽을 분산한다. 주로 TCP와 UDP 프로토콜을 기반으로 하며, 클라이언트와 서버 간의 패킷을 전달하는 방식으로 동작한다. 빠르지만 트래픽의 내용 분석이 어렵다.
- **L7 로드 밸런서 (애플리케이션 계층)**: HTTP, HTTPS 등의 애플리케이션 계층 정보를 기반으로 트래픽을 분산한다. 클라이언트 요청의 URL, 쿠키, 헤더 정보를 바탕으로 분산할 수 있어 다양한 분산 전략을 적용할 수 있다. 예를 들어, URL이 특정 패턴을 따르는 요청은 특정 서버로, 다른 패턴의 요청은 또 다른 서버로 분산하는 방식이다.

---

### 로드 밸런서의 종류

1. **소프트웨어 기반 로드 밸런서**
   - 소프트웨어를 통해 로드 밸런싱을 수행한다. 설정이 용이하고 저렴한 비용으로 사용 가능하여 유연한 확장성이 있다.
   - **예시**: NGINX, HAProxy, Traefik, AWS ELB (Elastic Load Balancing)
2. **하드웨어 기반 로드 밸런서**
   - 전용 하드웨어 장치를 통해 로드 밸런싱을 수행하며, 대규모 트래픽을 처리할 수 있다. 소프트웨어보다 높은 성능과 안정성을 제공한다.
   - **예시**: F5 Networks의 BIG-IP, Citrix NetScaler
3. **클라우드 기반 로드 밸런서**
   - 클라우드 서비스 제공자가 제공하는 로드 밸런서로, 서버를 추가하는 것이 쉽고 서비스 장애 시 자동으로 확장하여 대처할 수 있다.
   - **예시**: AWS의 ALB (Application Load Balancer), GCP의 Cloud Load Balancing, Azure의 Load Balancer

---

### 로드 밸런서의 주요 기능

1. **트래픽 분산**: 서버에 가해지는 부하를 분산하여 과부하를 방지한다.
2. **고가용성 및 장애 조치 (Failover)**: 서버 중 일부가 다운되더라도 다른 서버로 요청을 전환하여 서비스가 중단되지 않도록 한다.
3. **보안 강화**: SSL 인증서 적용을 통해 HTTPS 트래픽을 처리하며, DDoS 공격을 완화할 수 있다.
4. **세션 지속성 (Sticky Sessions)**: 특정 클라이언트가 동일한 서버로 연결될 수 있도록 한다. 로그인 정보가 필요한 서비스에서 유용하다.
5. **헬스 체크**: 서버의 상태를 주기적으로 확인하고, 응답하지 않는 서버는 트래픽 분배에서 제외한다.

---

### 로드 밸런서의 장점과 단점

#### 장점

- **성능 향상**: 서버 부하를 고르게 분산하여 서버 성능을 최적화하고 사용자 응답 시간을 단축시켜 준다.
- **확장성**: 수평 확장을 지원하여 서버 추가로 처리 능력을 쉽게 확장할 수 있다.
- **고가용성**: 서버 장애 시 다른 서버로 요청을 분산하여 중단 없는 서비스를 보장한다.

#### 단점

- **복잡성**: 설정과 관리가 복잡하며, 특히 세션 관리와 데이터 일관성을 고려해야 한다.
- **비용**: 소프트웨어 또는 하드웨어 기반 로드 밸런서 사용 시 추가 비용이 발생한다.
- **네트워크 지연**: 패킷을 한 번 더 처리해야 하므로 지연 시간이 소폭 증가할 수 있다.
